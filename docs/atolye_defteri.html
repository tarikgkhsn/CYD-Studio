1. Proje iskeleti

Bir mikrodenetleyici projesi her zaman aynı şekle sahiptir: kur → döngüde iş yap → çıkarken temizle. Arduino'da bunun adı setup()/loop(); MicroPython'da düz bir betiktir.

Genel
from machine import Pin
import time

led = Pin(2, Pin.OUT)      # kurulum
while True:                # sonsuz döngü
    led.value(1)
    time.sleep(0.5)
    led.value(0)
    time.sleep(0.5)

Durdurmanın yolu yok: fişi çekersin.

CYD Studio'da
projects/led_yakip_sondur.py 
import cyd
n = 0
try:
    while not cyd.should_stop():
        n += 1
        cyd.led(g=True)
        if not cyd.sleep(0.5): break
        cyd.led_off()
        if not cyd.sleep(0.5): break
finally:
    cyd.led_off()   # çıkarken yanık kalmasın
print('durduruldu - %d kez' % n)
Neden

while True yerine while not cyd.should_stop(): paneldeki Durdur düğmesi bir bayrak kaldırır; döngü her turda ona bakar ve temiz çıkar.

cyd.sleep() beklerken de bayrağı dinler ve kesilirse False döner — 30 saniyelik bir uykunun ortasında bile Durdur 3 sn içinde tutar.

try/finally: proje nasıl biterse bitsin donanım temiz kalır. Röle açık kalmış bir projeyi düşün.

Ölçüldü
Bayrağı dinlemeyen proje 3 sn sonra "takıldı" sayılır; tek çalışan oysa kart kendini resetler (~8 sn'de panel geri gelir). En kötü ihtimalde bile kart elinde kalmaz.

2. Pin: dijital giriş / çıkış

GPIO pini tek bir teldir; ya sürer (çıkış: 0 V ya da 3,3 V) ya dinler (giriş: dışarıdaki voltajı 0/1 okur). Eşik kabaca 0,8 V altı = 0, 2 V üstü = 1; arası belirsiz.

Genel
p = Pin(22, Pin.OUT)
p.value(1)          # 3,3 V
p.value(0)          # 0 V

g = Pin(27, Pin.IN, Pin.PULL_UP)
g.value()           # 0 ya da 1

Havada kalan giriş pini anten gibidir, rastgele okur. PULL_UP/PULL_DOWN "boşta ne olsun" sorusunun cevabıdır.

CYD Studio'da
projects/harici_led.py 
from machine import Pin
import cyd

# CYD: GPIO22. NodeMCU: D1 (GPIO5).
PIN = getattr(cyd, 'D1', 22)
led = Pin(PIN, Pin.OUT)
led.value(0)

while not cyd.should_stop():
    led.value(1)
    if not cyd.sleep(0.5): break
    led.value(0)
    if not cyd.sleep(0.5): break

Kart üstü RGB LED için pin bilmene gerek yok: cyd.led(r,g,b).

Neden

getattr(cyd, 'D1', 22): NodeMCU'da 22 numaralı pin yok — ValueError: invalid pin. Aynı dosya iki kartta çalışsın diye kartın verdiği etiketi soruyoruz. (Bu hata gerçekten yaşandı: proje "1 saniye çalışıp düştü" gibi göründü.)

CYD'de boş pin çok az: ekran, dokunmatik, SD ve LED çoğunu almış. Sana kalan 22, 27 ve sadece-giriş 35. Pin haritası §12'de.

Elektrik
Pin 3,3 V verir ve en fazla ~12 mA taşır. LED'e 220 Ω direnç şart; motor, röle, lamba pinden sürülmez (§6). 5 V çıkışlı bir şeyi giriş pinine doğrudan bağlama. Her şeyin GND'si ortak olmalı — ortak toprak yoksa hiçbir sinyal anlamlı değil.

3. Buton: yoklama mı, kesme mi

İki yol var. Yoklama (polling): döngüde pini okursun. Kesme (IRQ): donanım, pin değiştiği anda senin fonksiyonunu çağırır; sen döngüde sadece "kaç basış oldu" diye sorarsın.

Genel
# yoklama
b = Pin(22, Pin.IN, Pin.PULL_UP)
onceki = 1
while True:
    v = b.value()
    if onceki == 1 and v == 0:
        print('basildi')
    onceki = v
    time.sleep_ms(20)

# kesme
def isr(pin): sayac[0] += 1
b.irq(trigger=Pin.IRQ_FALLING, handler=isr)

Kablolama: buton bir ucu pine, diğeri GND'ye. Direnç yok, PULL_UP içeride; basılı = 0.

CYD Studio'da
projects/buton_ornek.py 
import cyd

def basinca(b):
    print('basis #%d' % b.sayac)   # kısa tut

b = cyd.buton(22, fn=basinca)      # pin ↔ GND
acik = False
while not cyd.should_stop():
    if b.basildi():                # son sorudan beri
        acik = not acik
        cyd.led(False, acik, False)
    cyd.sleep(0.05)

b.sayac toplam, b.basili() şu an, sekme_ms=40 titreşim süzme. Proje bitince kesme kendiliğinden kapanır.

Neden

Yoklama, döngün başka bir şeyle meşgulken basışı kaçırır. Kesme donanımdan sayar; sen 1 saniye sonra sorsan da basış orada durur.

Kesme fonksiyonunun içinde print, bellek ayırma, uzun iş yapılmaz; cyd.buton senin fn'ini kesme dışına (micropython.schedule) taşıdığı için orada print serbest, ama yine kısa tut.

Buton "sekme" yapar: bir basışta 5–10 titreşim. 40 ms içindeki tekrarlar sayılmaz.

4. Analog okuma (ADC)

Potansiyometre, LDR, NTC, pil seviyesi 0/1 değil, sürekli voltaj verir. ADC bunu sayıya çevirir. Her pin ADC yapamaz; giriş asla 3,3 V'u geçmemeli.

Genel
from machine import ADC, Pin
a = ADC(Pin(35))
a.atten(ADC.ATTN_11DB)   # ESP32: 0–3,3 V
ham = a.read()            # 0–4095
volt = ham / 4095 * 3.3

# NodeMCU: ADC(0).read() → 0–1023
LDR gibi direnç sensörü tek başına okunmaz, gerilim bölücü kurulur: 3,3V ──[ LDR ]──●──[ 10k ]── GND │ ADC pini
CYD Studio'da
projects/gece_lambasi.py (öz) 
dusuk = yuksek = None
yanik = False
while not cyd.should_stop():
    ham = cyd.light()           # CYD: GPIO34, NodeMCU: A0
    dusuk  = ham if dusuk  is None else min(dusuk, ham)
    yuksek = ham if yuksek is None else max(yuksek, ham)
    if n <= 8 or yuksek - dusuk < 20:
        cyd.sleep(0.3); continue   # hâlâ öğreniyor
    oran = (ham - dusuk) / (yuksek - dusuk)
    if not yanik and oran < 0.5 - 0.12:
        yanik = True;  cyd.led(True, True, True)
    elif yanik and oran > 0.5 + 0.12:
        yanik = False; cyd.led_off()
    cyd.sleep(0.3)
Neden

Sabit eşik yazma. "ham < 2000 ise karanlık" her odada, her kartta farklı sonuç verir (CYD 0–4095, NodeMCU 0–1023 döner). Proje ilk 8 ölçümde en düşük/en yüksek değeri öğrenip eşiği oran olarak kurar.

Histerezis (%12 ölü bant): eşiğin tam üstünde gezen değer LED'i titretir. Yanmak için 0,38'in altına, sönmek için 0,62'nin üstüne çıkması gerekir.

Gürültülü analogda ayrıca 5–10 ölçümün ortalamasını almak yaygındır.

Ölçüldü
CYD'nin kart üstü LDR'si (GPIO34) çalışıyor ama aralığı dar: oda ışığında ~146/4095, elle kapatınca ~80. Bu yüzden proje ölçeği kendisi öğreniyor.

5. Zaman ve bekleme

Üç ayrı ihtiyaç var: beklemek, süre ölçmek, periyodik iş yapmak. Hepsini sleep ile çözmeye çalışmak klasik hata.

Genel
import time
time.sleep(1)          # beklemek (bloke)
time.sleep_ms(20)

t0 = time.ticks_ms()   # süre ölçmek
...
gecen = time.ticks_diff(time.ticks_ms(), t0)

# periyodik: sleep ile DEĞİL, saatle
son = time.ticks_ms()
while True:
    if time.ticks_diff(time.ticks_ms(), son) >= 1000:
        son = time.ticks_ms()
        olc()
    kisa_isler()

ticks_ms() taşar (sarar); farkı her zaman ticks_diff ile al, çıkarma yapma.

CYD Studio'da
projects/hareket_led.py (ısınma bölümü) 
ISINMA_SN = 45
basla = time.ticks_ms()
while not cyd.should_stop():
    if time.ticks_diff(time.ticks_ms(), basla) >= ISINMA_SN * 1000:
        break                       # 45 sn doldu

PIR sensörü ilk 45 sn'de saçmalar; proje o süreyi bekler ama kilitlenmez: LED yanıp söner, Durdur çalışır.

Neden

time.sleep(45) yazsaydık: 45 sn boyunca Durdur işlemez, panel o projeyi "takıldı" sanır. Uzun süreyi kısa uykular + saat ile geçiriyoruz.

Bekleme süresi ne olmalı? Buton 20–50 ms, sensör 0,5–2 sn, ekran yenileme 100–500 ms. Daha sık okumak kazandırmaz, sadece komşu projelerden zaman çalar.

Normal modda (§8) cyd.sleep aynı zamanda diğer projelere sıra verdiğin andır — hiç sleep'siz döngü komşuları bekletir.

6. Güç: LED, röle, ULN2803, PWM

Pin bir sinyaldir, güç kaynağı değil. Kural: pin sadece tetikler; yükü başka bir şey sürer.

Genel
LED (≤ 12 mA): pin ──[220Ω]──▶|── GND Röle / motor / 12 V lamba — ULN2803A: pin ──▶ ULN giriş (1B) ULN COM ── +12 V ← flyback diyotları için ULN çıkış (1C) ── yükün (−) ucu yükün (+) ucu ── +12 V ULN GND ── kart GND ── adaptör (−) ← ortak toprak
# "analog çıkış" yok: PWM var
from machine import PWM
pwm = PWM(Pin(22), freq=1000)
pwm.duty(512)      # %50 parlaklık (ESP32 0–1023)
CYD Studio'da
projects/uln2803_yuk.py (öz) 
KANALLAR = (27,)
pinler = [Pin(p, Pin.OUT, value=0) for p in KANALLAR]

value=0 ile kurmak: pin açıldığı an yük kapalı. Röleyi "bir an tık" diye açmamak için.

Neden

Dirençsiz LED 100 mA+ çeker; ESP32 pini 12 mA içindir — pin ya da çip gider.

ULN2803 sekiz Darlington transistör + flyback diyot: motor/röle bobini kapanırken oluşan ters gerilimi yutar. Transistörü tek tek kurmaktansa tek çip.

Kartın 3,3 V regülatörü küçük: sensörleri besler, motoru beslemez. Motorun kendi kaynağı olur, toprak ortaklanır.

ESP8266'da PWM 0–1023, Pico'da duty_u16 0–65535 — sayı kartta değişir, fikir değişmez.

Genel

Bir kartta iki işi aynı anda yapmanın iki klasik yolu: thread (işletim sistemi sırayla koşturur, her birinin kendi yığını) ve işbirlikçi görev (asyncio: her görev await dediğinde sırayı bırakır, tek yığın).

import asyncio
async def led():
    while True:
        ...; await asyncio.sleep(0.5)
async def sensor():
    while True:
        ...; await asyncio.sleep(2)
asyncio.run(asyncio.gather(led(), sensor()))
CYD Studio'da

Sen düz yazarsın:

while not cyd.should_stop():
    ...
    cyd.sleep(0.5)

Normal modda sistem bunu satır satır async def içine sarar, cyd.sleep( → await yapar, geçici dosyaya yazıp oradan derler. Sen async görmezsin.

Bekleme çağrısı bir def içindeyse dönüşüm uymaz → proje kendiliğinden T'de açılır, log nedenini yazar.

İstersen kendin de yazabilirsin: dosyada async def main(): varsa dokunulmaz.

Neden thread değil

Thread'in yığını dahili DRAM'den çıkar: proje başına 10–15 KB. Panel açıkken 55 KB var → en fazla 3–4 proje. Normal modda görev başına dahili RAM 0.

Ölçüldü: 7 küçük proje yan yana, dahili RAM 37 KB'de sabit kaldı; sınır heap oldu. ESP8266'da (thread hiç yok) 3 proje.

Bedeli: tek iş parçacığı olduğu için sleep'siz proje komşularını bekletir. O yüzden T var.

9. Projenin web sayfası

Bir projenin telefondan kontrol edilmesi istenir: "yükü aç/kapat", "sıcaklığı göster". Klasik yol projenin kendi HTTP sunucusunu açmasıdır. Bizde yasak — ve daha kolayı var.

Genel
import socket
s = socket.socket()
s.bind(('0.0.0.0', 8080)); s.listen(1)
while True:
    c, a = s.accept()
    istek = c.recv(512)
    c.send(b'HTTP/1.1 200 OK\r\n\r\n<h1>selam</h1>')
    c.close()

Her projede aynı 15 satır, ikinci port, isteği elle ayrıştırma.

Sayfa http://<kart>/yuk'ta, panelde "Uygulamalar:" satırında link olarak görünür.

Neden

İkinci dinleyici soket lwIP tamponlarıyla dahili RAM'i yiyor: ölçüldü, panel kilitlendi. Tek soket, tek port, aynı sunucu.

İşleyici sunucunun iş parçacığında koşar: içinde bekleme yapma, sadece değişken oku/yaz. Asıl işi (pin sürme) ana döngü yapar — sayfa ile proje bir değişken üzerinden konuşur (mod).

Proje bitince rotalar silinir; başka bir projenin /yuk'u kalmaz.

14. Yeni modül: datasheet'ten sürücüye

Elinde hiç görmediğin bir modül var; internetteki kütüphane kartına uymuyor ya da yok. Sürücü yazmak sanıldığından kısa: datasheet'ten üç bilgi alırsın, gerisi §7'deki I2C çağrılarıdır. Örnek: PCF8574 I2C giriş/çıkış çoklayıcı (8 ek pin, LCD1602 "backpack"lerin altındaki çip).

Datasheet'ten alınacak üç şey

1. Adres: PCF8574 0x20–0x27 (A0–A2 pinleri), PCF8574A 0x38–0x3F. i2c.scan() hangisi olduğunu söyler.

2. Protokol: kayıt yok. Bir byte yazarsan 8 çıkış o olur; bir byte okursan 8 pinin durumu gelir. Bit 0 = P0 … bit 7 = P7.

3. Tuhaflık: "yarı-çift yönlü" pinler. Giriş olarak kullanacağın pine önce 1 yaz (zayıf pull-up), sonra oku. Çıkış olarak 0 yazınca güçlü çeker (LED'i GND'ye değil VCC'ye bağla, 0 = yanık), 1 yazınca sadece zayıf 100 µA verir. INT pini herhangi bir giriş değişince LOW'a düşer.

Sürücü: 20 satır
projects/pcf8574.py 
class PCF8574:
    def __init__(self, i2c, adres=0x20):
        self.i2c = i2c
        self.adres = adres
        self.cikis = 0xFF          # hepsi 1: giriş/boşta
        self._yaz()

    def _yaz(self):
        self.i2c.writeto(self.adres, bytes([self.cikis]))

    def pin_yaz(self, p, deger):   # p: 0–7
        if deger: self.cikis |= (1 << p)
        else:     self.cikis &= ~(1 << p) & 0xFF
        self._yaz()

    def oku(self):                 # 8 pin, byte
        return self.i2c.readfrom(self.adres, 1)[0]

    def pin_oku(self, p):
        return (self.oku() >> p) & 1

1. Project skeleton

A microcontroller project always has the same shape: set up → do work in a loop → clean up on exit. Arduino calls it setup()/loop(); in MicroPython it is a plain script.

General
from machine import Pin
import time

led = Pin(2, Pin.OUT)      # setup
while True:                # forever
    led.value(1)
    time.sleep(0.5)
    led.value(0)
    time.sleep(0.5)

No way to stop it: you pull the plug.

In CYD Studio
projects/led_yakip_sondur.py 
import cyd
n = 0
try:
    while not cyd.should_stop():
        n += 1
        cyd.led(g=True)
        if not cyd.sleep(0.5): break
        cyd.led_off()
        if not cyd.sleep(0.5): break
finally:
    cyd.led_off()   # never leave it lit
print('stopped - %d blinks' % n)
Why

while not cyd.should_stop() instead of while True: the panel's Stop button raises a flag; the loop checks it every turn and exits cleanly.

cyd.sleep() watches the flag while waiting and returns False when interrupted — Stop lands within 3 s even in the middle of a 30-second sleep.

try/finally: however the project ends, the hardware is left clean. Think of a relay left switched on.

Measured
A project that ignores the flag is marked "stuck" after 3 s; if it is the only one running the board resets itself (panel back in ~8 s). Even in the worst case the board is never lost.

2. Pins: digital in / out

A GPIO pin is one wire; it either drives (output: 0 V or 3.3 V) or listens (input: reads the outside voltage as 0/1). Threshold roughly: below 0.8 V = 0, above 2 V = 1; in between is undefined.

General
p = Pin(22, Pin.OUT)
p.value(1)          # 3.3 V
p.value(0)          # 0 V

g = Pin(27, Pin.IN, Pin.PULL_UP)
g.value()           # 0 or 1

A floating input is an antenna and reads noise. PULL_UP/PULL_DOWN answers "what is it when nothing is connected".

In CYD Studio
projects/harici_led.py 
from machine import Pin

For the on-board RGB LED you need no pin number: cyd.led(r,g,b).

Why

getattr(cyd, 'D1', 22): the NodeMCU has no pin 22 — ValueError: invalid pin. We ask the board for its label so the same file runs on both. (This really happened: the project looked like it "ran one second and died".)

The CYD has very few free pins: display, touch, SD and LED take most. Yours are 22, 27 and input-only 35. Pin map in §12.

Electrical
A pin gives 3.3 V and carries at most ~12 mA. An LED needs a 220 Ω resistor; motors, relays, lamps are never driven from a pin (§6). Never wire a 5 V output straight into an input pin. Everything shares one GND — without a common ground no signal means anything.

3. Buttons: polling or interrupt

Two ways. Polling: read the pin in the loop. Interrupt (IRQ): the hardware calls your function the moment the pin changes; in the loop you only ask "how many presses so far".

General
# polling
b = Pin(22, Pin.IN, Pin.PULL_UP)
prev = 1
while True:
    v = b.value()
    if prev == 1 and v == 0:
        print('pressed')
    prev = v
    time.sleep_ms(20)

# interrupt
def isr(pin): count[0] += 1
b.irq(trigger=Pin.IRQ_FALLING, handler=isr)

Wiring: one leg to the pin, the other to GND. No resistor, PULL_UP is internal; pressed = 0.

In CYD Studio
projects/buton_ornek.py 
import cyd

def on_press(b):
    print('press #%d' % b.sayac)   # keep it short

b = cyd.buton(22, fn=on_press)     # pin ↔ GND

    if b.basildi():                # presses since last ask
        on = not on
        cyd.led(False, on, False)
    cyd.sleep(0.05)

b.sayac total, b.basili() held right now, sekme_ms=40 debounce. The IRQ is released when the project ends.

Why

Polling misses a press while your loop is busy elsewhere. The interrupt counts in hardware; ask a second later and the press is still there.

Inside an IRQ handler: no print, no allocation, nothing long. cyd.buton moves your fn out of the IRQ (micropython.schedule), so print is allowed there — still keep it short.

Buttons bounce: one press is 5–10 edges. Repeats within 40 ms are not counted.

Potentiometers, LDRs, NTCs, battery level give a continuous voltage, not 0/1. The ADC turns it into a number. Not every pin has an ADC; the input must never exceed 3.3 V.

In CYD Studio
projects/gece_lambasi.py (core) 
low = high = None

    cyd.sleep(0.3)
Why

Never hard-code a threshold. "raw < 2000 means dark" differs per room and per board (CYD returns 0–4095, NodeMCU 0–1023). The project learns min/max over the first 8 readings and sets the threshold as a ratio.

Hysteresis (12% dead band): a value hovering at the threshold would flicker the LED. It must drop below 0.38 to switch on and rise above 0.62 to switch off.

For noisy analog inputs averaging 5–10 samples is common too.

Measured
The CYD's on-board LDR (GPIO34) works but its range is narrow: ~146/4095 in room light, ~80 when covered. That is why the project learns its own scale.

5. Time and waiting

Three separate needs: waiting, measuring a duration, doing something periodically. Solving all three with sleep is the classic mistake.

General
import time
time.sleep(1)          # wait (blocking)
time.sleep_ms(20)

t0 = time.ticks_ms()   # measure
...
elapsed = time.ticks_diff(time.ticks_ms(), t0)

# periodic: by the clock, NOT by sleep
last = time.ticks_ms()
while True:
    if time.ticks_diff(time.ticks_ms(), last) >= 1000:
        last = time.ticks_ms()
        measure()
    short_work()

ticks_ms() wraps around; always use ticks_diff, never plain subtraction.

In CYD Studio
projects/hareket_led.py (warm-up part) 
WARMUP_S = 45
start = time.ticks_ms()
while not cyd.should_stop():
    if time.ticks_diff(time.ticks_ms(), start) >= WARMUP_S * 1000:
        break                       # 45 s over
    led(True)
    if not cyd.sleep(0.12): break   # blink meanwhile
    led(False)
    if not cyd.sleep(0.12): break

A PIR sensor is erratic for its first 45 s; the project waits without locking up: the LED blinks, Stop works.

Why

With time.sleep(45) Stop would be ignored for 45 s and the panel would call the project stuck. Long waits are done as short sleeps + the clock.

How long to sleep? Buttons 20–50 ms, sensors 0.5–2 s, screen refresh 100–500 ms. Reading more often gains nothing; it only steals time from neighbour projects.

In normal mode (§8) cyd.sleep is also the moment you hand the turn to other projects — a loop with no sleep stalls its neighbours.

6. Power: LEDs, relays, ULN2803, PWM

A pin is a signal, not a power supply. Rule: the pin only triggers; something else drives the load.

General
LED (≤ 12 mA): pin ──[220Ω]──▶|── GND Relay / motor / 12 V lamp — ULN2803A: pin ──▶ ULN input (1B) ULN COM ── +12 V ← for the flyback diodes ULN output (1C) ── load (−) load (+) ── +12 V ULN GND ── board GND ── adapter (−) ← common ground
# there is no "analog out": PWM instead
from machine import PWM
pwm = PWM(Pin(22), freq=1000)

In CYD Studio
projects/uln2803_yuk.py (core) 
CHANNELS = (27,)
pins = [Pin(p, Pin.OUT, value=0) for p in CHANNELS]

def all_(v):
    for p in pins: p.value(v)

try:
    while not cyd.should_stop():

        if not cyd.sleep(PERIOD): break
        all_(0); screen(False, turn)
        if not cyd.sleep(PERIOD): break

Creating with value=0: the load is off the instant the pin exists — no relay "click" at start.

Why

An LED without a resistor draws 100 mA+; an ESP32 pin is rated for 12 mA — the pin or the chip dies.

The ULN2803 is eight Darlington transistors plus flyback diodes: it absorbs the reverse spike a motor/relay coil produces when switched off. One chip instead of building transistor stages.

The board's 3.3 V regulator is small: it feeds sensors, not motors. The motor gets its own supply; grounds are joined.

ESP8266 PWM is 0–1023, the Pico uses duty_u16 0–65535 — the number changes per board, the idea does not.

Why not threads

A thread's stack comes out of internal DRAM: 10–15 KB per project. With the panel up there is 55 KB → 3–4 projects at most. In normal mode a task costs 0 internal RAM.

Measured: 7 small projects side by side, internal RAM flat at 37 KB; the heap became the limit. On the ESP8266 (no threads at all) 3 projects.

The price: one thread, so a project without sleep stalls its neighbours. That is what T is for.

Wiring a new sensor

  1. Datasheet: supply 3.3 or 5 V, output digital / analog / I2C / UART → which kind of pin.
  2. Wire VCC, GND, signal. If I2C, run i2c_tara.py → the address must appear.

14. A new module: from datasheet to driver

You hold a module you have never seen; the library online doesn't fit your board or doesn't exist. Writing a driver is shorter than it sounds: take three facts from the datasheet, the rest is the I2C calls from §7. Example: the PCF8574 I2C I/O expander (8 extra pins; the chip under every LCD1602 "backpack").

Three things from the datasheet

1. Address: PCF8574 0x20–0x27 (A0–A2 pins), PCF8574A 0x38–0x3F. i2c.scan() tells you which.

2. Protocol: no registers. Write one byte and the 8 outputs become it; read one byte and you get the 8 pin states. Bit 0 = P0 … bit 7 = P7.

3. The quirk: "quasi-bidirectional" pins. A pin you want as an input must be written 1 first (weak pull-up), then read. As an output, writing 0 sinks strongly (wire the LED to VCC, 0 = lit); writing 1 sources only a weak 100 µA. The INT pin goes LOW whenever any input changes.

The driver: 20 lines
projects/pcf8574.py 
class PCF8574:
    def __init__(self, i2c, addr=0x20):
        self.i2c = i2c
        self.addr = addr
        self.out = 0xFF            # all 1: inputs / idle
        self._write()

    def _write(self):
        self.i2c.writeto(self.addr, bytes([self.out]))

    def pin_write(self, p, v):     # p: 0–7
        if v: self.out |= (1 << p)
        else: self.out &= ~(1 << p) & 0xFF
        self._write()

    def read(self):                # 8 pins, one byte
        return self.i2c.readfrom(self.addr, 1)[0]

    def pin_read(self, p):
        return (self.read() >> p) & 1
In a project, and why
projects/pcf_example.py 
import cyd
from machine import SoftI2C, Pin
from pcf8574 import PCF8574

i2c = SoftI2C(scl=Pin(27), sda=Pin(22))

    pressed = x.pin_read(0) == 0
    x.pin_write(7, 0 if pressed else 1)   # P7 LED (to VCC)
    cyd.sleep(0.05)

Keeping the class in its own file: the module is unloaded when the project ends, so a fix runs next time. Polling at 50 ms: there is no interrupt over I2C (unless you wire INT to a board pin and catch it with cyd.buton(pin)). The PCF8574 is about pin count, not speed: it adds 8 to the CYD's 2 free pins.

The general order when writing a driver
1) See the address with scan(). 2) Read the ID register from the datasheet's register map (if there is one, e.g. BME280 0xD0 → 0x60): it proves you reached the right chip. 3) Print one measurement as raw bytes. 4) Apply the datasheet's conversion formula. 5) Wrap it in a class with a read(). print at every step — never move on before the previous step works.
